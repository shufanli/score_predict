## 🔄 数据流转详解

### 1️⃣ 用户提交问卷
```javascript
用户填写 30 道题
    ↓
提交按钮触发 (test.html line 1764)
    ↓
收集所有答案 FormData
    ↓
验证是否全部回答
```

### 2️⃣ 分数计算
```javascript
遍历所有答案
    ↓
应用计分规则:
  - 第1题: 特殊分值映射 (300-600分档位)
  - 第30题: 特殊分值映射 × 0.7
  - 其他题: 标准 7 点量表计分
    ↓
计算各维度得分:
  - section1: 题 1-9   (学习基础与潜力)
  - section2: 题 10-17 (心理抗压能力)
  - section3: 题 18-23 (方法与规划能力)
  - section4: 题 24-30 (目标与动机)
    ↓
汇总总分
```

### 3️⃣ 数据存储（双轨制）
```javascript
┌─────────────────────────────┐
│  准备数据对象               │
│  {                          │
│    totalScore,              │
│    sectionScores,           │
│    answers                  │
│  }                          │
└─────────────────────────────┘
         │
         ├──────────────┬──────────────┐
         ↓              ↓              ↓
    轨道1: 本地      轨道2: 云端    立即跳转
    localStorage    Supabase       result.html
    (同步)          (异步)         (用户看结果)
         │              │
         ↓              ↓
    永久保存        后台上传
    浏览器中        (不阻塞)
```

**优势**:
- ✅ 本地存储保证用户一定能看到结果
- ✅ 云端存储实现数据持久化和统计
- ✅ 异步上传不影响用户体验

### 4️⃣ 结果展示
```
result.html 页面
    ↓
从 localStorage 读取数据
    ↓
根据总分给出建议:
  - ≥70分: 适合复读，提分潜力大
  - 40-70分: 需谨慎评估
  - <40分: 复读风险较高
    ↓
展示各维度雷达图和详细分析
```

### 5️⃣ 管理员查看统计
```
admin.html 页面
    ↓
连接 Supabase 数据库
    ↓
查询 survey_results 表
    ↓
计算统计数据:
  - 总提交数
  - 平均分、最高分、最低分
  - 各维度平均分
  - 分数段分布
    ↓
可视化展示 + 最近记录表格
```

## 🗄️ 数据库设计

### 主表: survey_results
```sql
┌─────────────────┬──────────────────┬────────────────────┐
│     字段名      │     数据类型      │        说明         │
├─────────────────┼──────────────────┼────────────────────┤
│ id              │ UUID             │ 主键，自动生成       │
│ created_at      │ TIMESTAMP        │ 提交时间            │
│ total_score     │ NUMERIC          │ 总分                │
│ section1_score  │ NUMERIC          │ 学习基础与潜力得分   │
│ section2_score  │ NUMERIC          │ 心理抗压能力得分     │
│ section3_score  │ NUMERIC          │ 方法与规划能力得分   │
│ section4_score  │ NUMERIC          │ 目标与动机得分       │
│ answers         │ JSONB            │ 所有答案(q1-q30)    │
└─────────────────┴──────────────────┴────────────────────┘
```

### 视图 1: survey_statistics
提供快速统计查询：
```sql
SELECT 
    COUNT(*) as total_surveys,      -- 总提交数
    AVG(total_score) as avg_score,  -- 平均分
    AVG(section1_score),            -- 各维度平均分
    AVG(section2_score),
    AVG(section3_score),
    AVG(section4_score),
    MAX(total_score),               -- 最高分
    MIN(total_score)                -- 最低分
FROM survey_results;
```

### 视图 2: daily_survey_stats
按日期统计：
```sql
SELECT 
    DATE(created_at) as survey_date,
    COUNT(*) as daily_count,
    AVG(total_score) as daily_avg_score
FROM survey_results
GROUP BY DATE(created_at);
```

## 🔐 安全机制

### 前端安全
1. **密码保护**: index.html 验证密码才能进入
2. **表单验证**: 必须完成所有 30 题才能提交
3. **数据验证**: JavaScript 层面验证数据完整性

### 后端安全 (Supabase)
1. **RLS 策略**: Row Level Security 控制数据访问
2. **API Key 分离**: anon key（前端）vs service key（后端）
3. **HTTPS 传输**: 所有数据加密传输

### 推荐的 RLS 策略
```sql
-- 允许匿名插入
CREATE POLICY "allow_insert" ON survey_results
FOR INSERT TO anon
WITH CHECK (true);

-- 限制查询（可选，看需求）
CREATE POLICY "allow_select" ON survey_results
FOR SELECT TO authenticated  -- 仅认证用户可查询
USING (true);
```

## 📊 数据分析场景

### 场景 1: 查看整体情况
```sql
SELECT * FROM survey_statistics;
```

### 场景 2: 找出高潜力学生
```sql
SELECT * FROM survey_results 
WHERE total_score >= 70
ORDER BY total_score DESC;
```

### 场景 3: 分析薄弱维度
```sql
SELECT 
    AVG(section1_score) as 学习基础,
    AVG(section2_score) as 心理抗压,
    AVG(section3_score) as 方法规划,
    AVG(section4_score) as 目标动机
FROM survey_results;
```

### 场景 4: 按时间段统计
```sql
SELECT 
    DATE_TRUNC('week', created_at) as week,
    COUNT(*) as 提交数,
    AVG(total_score) as 平均分
FROM survey_results
GROUP BY week
ORDER BY week DESC;
```

### 场景 5: 查看具体答案分布
```sql
SELECT 
    answers->>'q1' as 第1题答案,
    COUNT(*) as 人数
FROM survey_results
GROUP BY answers->>'q1'
ORDER BY 人数 DESC;
```
