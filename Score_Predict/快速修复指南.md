## 🔍 故障排查

### 如果仍然提交失败

#### 错误 1: "new row violates row-level security policy"

**原因**: 权限策略未正确设置

**解决**:
1. 确认已执行 `set-permissions.sql`
2. 在 SQL Editor 中运行以下查询验证：
   ```sql
   SELECT * FROM pg_policies WHERE tablename = 'survey_results';
   ```
3. 应该看到两条策略记录

#### 错误 2: 控制台显示 "Supabase 未配置"

**原因**: 配置文件加载问题

**解决**:
1. 确认 `supabase-config.js` 中的 URL 和 Key 正确
2. 在浏览器控制台运行：
   ```javascript
   console.log(SUPABASE_CONFIG);
   ```
3. 应该显示你的配置信息（不是 'YOUR_SUPABASE_URL'）

#### 错误 3: "Failed to fetch" 或网络错误

**原因**: 网络问题或 Supabase 项目未激活

**解决**:
1. 检查网络连接
2. 访问 Supabase 控制台，确认项目状态为 "Active"
3. 如果项目被暂停，点击 "Restore" 恢复

#### 错误 4: 控制台没有任何 Supabase 相关消息

**原因**: 文件加载顺序问题

**解决**:
1. 确认 `test.html` 的 `<head>` 部分包含：
   ```html
   <!-- Supabase JavaScript SDK -->
   <script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
   
   <!-- Supabase 配置文件 -->
   <script src="supabase-config.js"></script>
   ```
2. 检查文件路径是否正确
3. 强制刷新页面

## 💡 重要提示

### ⚠️ 必须先设置权限
在执行 `set-permissions.sql` 之前，数据无法插入到数据库。这是 Supabase 的安全机制。

### 📁 文件位置
确保以下文件在同一目录：
- test.html
- supabase-config.js
- index.html
- result.html
- admin.html

### 🌐 访问方式
- ✅ 通过 HTTP 服务器访问（推荐）
- ✅ 直接打开 HTML 文件（可能有限制但应该能用）
- ❌ 避免跨域问题

### 🔒 权限说明
`set-permissions.sql` 设置的权限允许：
- ✅ 任何人可以插入数据（适合公开问卷）
- ✅ 任何人可以读取数据（用于统计）

如果这是内部问卷，可以修改策略限制访问。
