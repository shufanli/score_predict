## 🔧 修改的文件

### `test.html`
**修改位置**: 
1. **Head 部分** (第 7-10 行): 添加了 Supabase SDK 和配置文件的引用
2. **提交逻辑** (第 1829-1847 行): 在保存到 localStorage 后，同时提交数据到 Supabase

**核心逻辑**:
```javascript
// 保存到本地
localStorage.setItem('testResults', JSON.stringify(resultsData));

// 同时保存到 Supabase (异步，不阻塞)
submitToSupabase(resultsData).then(result => {
    if (result.success) {
        console.log('✅ 数据已成功保存到 Supabase');
    }
});

// 立即跳转到结果页面
window.location.href = 'result.html';
```

**优点**:
- 不影响用户体验，即使 Supabase 提交失败也不会阻塞页面跳转
- 数据双重保存（本地 + 云端），更加可靠
- 在浏览器控制台可以看到提交状态

- 使用 Supabase 的 anon public key（可安全地在前端使用）
- 支持 Row Level Security (RLS) 权限控制
- 可配置数据访问策略

### 📊 数据结构
每条问卷记录包含：
- `id`: UUID 唯一标识符
- `created_at`: 提交时间
- `total_score`: 总分
- `section1_score`: 学习基础与潜力得分
- `section2_score`: 心理抗压能力得分
- `section3_score`: 方法与规划能力得分
- `section4_score`: 目标与动机得分
- `answers`: 所有 30 道题的答案（JSONB 格式）

## 🚀 快速开始

### 步骤 1: 创建 Supabase 项目
访问 https://supabase.com，注册并创建一个新项目

### 步骤 2: 创建数据表
在 Supabase SQL Editor 中执行 `setup-supabase.sql`

### 步骤 3: 配置密钥
修改 `supabase-config.js`，填入你的项目 URL 和 anon key

### 步骤 4: 设置权限
执行以下 SQL 语句允许数据插入：
```sql
CREATE POLICY "允许公开插入" ON survey_results
FOR INSERT TO anon
WITH CHECK (true);
```

### 步骤 5: 测试
打开 `test.html` 完成问卷，检查浏览器控制台是否显示成功消息

### 步骤 6: 查看数据
- 方法 1: 在 Supabase Table Editor 中查看
- 方法 2: 打开 `admin.html` 查看统计面板

## 💡 最佳实践

1. **定期备份**: Supabase 提供自动备份，但建议定期手动导出重要数据
2. **监控使用量**: 在 Supabase Dashboard 中查看存储和带宽使用情况
3. **权限管理**: 根据需求配置合适的 RLS 策略
4. **数据清理**: 可设置定时任务自动清理过期数据

## ⚠️ 注意事项

1. **不要公开你的密钥**: 虽然 anon key 可以在前端使用，但不建议提交到公开的 GitHub 仓库
2. **免费版限制**: 
   - 500 MB 数据库存储
   - 1 GB 文件存储
   - 每月 2 GB 数据传输
3. **数据隐私**: 确保遵守相关数据保护法规
4. **项目暂停**: 免费版项目 7 天无活动会暂停（但数据不会丢失）

## 🔍 故障排查

### 问题: 提交失败
**检查**:
1. Supabase URL 和 Key 是否正确配置
2. 是否已创建数据表
3. 是否已设置 RLS 权限策略
4. 浏览器控制台是否有错误信息

### 问题: 看不到数据
**检查**:
1. 在 Supabase Table Editor 中确认数据是否存在
2. 检查 `admin.html` 的控制台是否有错误
3. 确认使用的是同一个 Supabase 项目

### 问题: 速度慢
**解决方案**:
1. 选择地理位置更近的 Supabase 服务器
2. 考虑将 SDK 下载到本地而非使用 CDN
3. 创建合适的数据库索引
